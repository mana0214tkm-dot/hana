# 人生ときめき育成記

GMOデザインアワード 2026「ときめき」テーマ向けの作品です。

## コンセプト

就活がうまくいかず悩んでいたときに「こんなアプリがあったらいいな」と思って作りました。
仕事だけでなく、**人生を支える4本の柱**をまるごと育成ゲームにしています。

- 🌱 **仕事・キャリア** … 就活 → 入社 → 中堅 → 管理職 → ベテラン → 定年まで
- 💖 **恋愛・結婚** … 出会い → おつきあい → 結婚 → 金婚式まで
- ⭐ **推し活** … 出会ったばかりのファン → 布教マスター → 推しと歩む人生まで
- 💰 **お金・資産形成** … 一粒の種銭 → 貯金 → 資産形成 → 経済的自由まで

日々の小さな行動(面接を受けた、デートに行った、ライブに参戦した、貯金した、など)を記録するたびに
それぞれの柱にポイントが貯まり、専用のキャラクターが8段階で成長していきます。
結果が出なくてもいい。頑張った"行動"そのものが、そのままときめく成長として形に残ります。

## 主な機能

- ✅ 4本柱(仕事/恋愛・結婚/推し活/お金)それぞれに専用の育成キャラクターとステージ
- ✅ 柱ごとに異なるカテゴリ(合計20種類)で日々の記録を追加
- ✅ 記録に応じてキャラクターが8段階で成長
- ✅ 次のステージまでの進捗バー
- ✅ 柱ごとの連続記録日数(ストリーク)の可視化
- ✅ 柱ごとの直近5週間のヒートマップ
- ✅ 柱ごとのカテゴリ別記録数集計
- ✅ 柱ごとのタイムライン表示・削除(削除時は確認ダイアログあり)
- ✅ 記録に写真を最大4枚添付可能(その場でリサイズ・圧縮してから保存、タップで拡大表示・矢印で前後の写真に切り替え)
- ✅ 記録はデータベース(Turso/libSQL、未設定時はローカルSQLiteファイル)に保存(旧localStorageのデータは初回起動時に自動移行)
- ✅ データウェアハウス層(記録のINSERT/DELETE時にトリガーで自動集計)による「ときめきアナリティクス」パネル
  - 柱ごとの累計ポイント・直近30日間の推移・よく使うカテゴリを常に最新の集計から表示
- ✅ 4本柱すべてのキャラクターが「花が育つ8段階」のイラストで表現される、ときめきデザイン
- ✅ 4本柱の合計進捗度に応じて、ページ全体の背景(色味・咲く花の数)が進化する演出

## 使い方

### ローカル開発(Tursoアカウント不要)

1. `npm install`
2. `npm run dev`
3. `http://localhost:3000` を開く

初回起動時に `data/app.db` が自動生成され、以降の記録・写真・データウェアハウス集計はすべてここに保存されます。

### Tursoに接続する場合(本番・複数端末同期向け)

1. [Turso](https://turso.tech/) でデータベースを作成し、接続URLと認証トークンを発行する
2. `.env.example` を `.env.local` にコピーし、`TURSO_DATABASE_URL` / `TURSO_AUTH_TOKEN` を設定する
3. `npm run dev`(または本番デプロイ)すると、以降はTurso上のデータベースに記録が保存される

環境変数が未設定の場合は自動的にローカルファイルDBにフォールバックするため、開発中はTursoを用意しなくても動作します。

## 技術スタック

- Next.js 16(App Router、Route Handlers)
- TypeScript
- Zustand(クライアント側の状態管理。永続化はサーバーAPI経由)
- @libsql/client(Turso/libSQL対応のデータベースクライアント + トリガーベースのデータウェアハウス)
- CSS カスタムプロパティ

## データベース設計

- `logs` … 記録本体(柱・カテゴリ・タイトル・メモ・獲得ポイントなど)
- `log_photos` … 記録に紐づく写真(1記録につき最大4枚、削除時は明示的なトランザクションでカスケード削除)
- `dwh_daily_pillar_stats` / `dwh_category_stats` … 分析用の集計テーブル(データウェアハウス)。
  `logs` へのINSERT/DELETEをトリガーが検知し、生ログを都度集計することなく常に最新の状態を保つ。
  `/api/warehouse` はこの集計テーブルだけを読むため、記録数が増えても分析表示が重くならない。

## デプロイ(Vercel)

1. GitHubにリポジトリをプッシュする
2. [Vercel](https://vercel.com/) でこのリポジトリをインポートする
3. 環境変数に `TURSO_DATABASE_URL` / `TURSO_AUTH_TOKEN` を設定する(Vercelはサーバーレス環境のため、ファイルDBではなくTursoが必須)
4. デプロイすれば完了

## デバッグ(VS Code)

`.vscode/launch.json` にNext.js公式のデバッグ構成を用意しています。VS Codeのデバッグパネルから
「Next.js: debug full stack」を選んで実行すると、サーバー側・クライアント側どちらもブレークポイントで止められます。
